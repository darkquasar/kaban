# Kaban codebase map

Kaban provides a local memory service through CLI commands and an MCP stdio server.
The workspace version is `3.0.0-alpha.1`. SQLite stores records and governance state;
Tantivy provides the text index. `kaban-index` explicitly produces SCIP code snapshots.

## Workspace

| Path | Responsibility |
| --- | --- |
| `crates/kaban-core` | Models, IDs, configuration, ontologies and persistence traits |
| `crates/kaban-policy` | YAML denylist, normalization, scanning and audit signing |
| `crates/kaban-store-sqlite` | SQLite storage, records, claims, reconciliation, jobs, audit and change log |
| `crates/kaban-index-tantivy` | Tantivy text indexing and query adapter |
| `crates/kaban-api` | Service rules, content gates, governance, recall, ingestion and code context |
| `crates/kaban` | CLI, MCP tool adapters and the retained `kaban bench` command |
| `crates/kaban-ingest` | Document walking, extraction, chunking and ingestion pipeline |
| `crates/kaban-codegraph` | Code snapshot identity, discovery and read/query provider |
| `crates/kaban-index` | SCIP runner, isolation, output gating and snapshot publication |
| `tools/kaban-rust-scip` | Rust SCIP producer with its own pinned toolchain |
| `hooks/` | Optional host and Git integrations |
| `fixtures/`, `crates/*/tests/` | Required test inputs, producer fixtures and snapshots |

```text
+-------------+  service calls  +-------------+  store calls  +----------------+
| CLI / MCP   | ==============> | kaban-api   | =============> | SQLite/Tantivy |
+-------------+                 +-------------+                +----------------+
```

Keep persistence behind the store interfaces. CLI and MCP adapters share service
rules. Code snapshots use a separate SQLite reader and are never generated by `serve`.

## Build and verification

Rust is pinned in `rust-toolchain.toml`; workspace dependencies and exact resolutions
live in `Cargo.toml` and `Cargo.lock`. Bundled SQLite requires a C compiler.

```sh
cargo build --locked --release -p kaban -p kaban-index
cargo test --locked --workspace
bash scripts/ci/ci.sh
```

Default CLI features are `ingest`, `code-graph` and `text-index-tantivy`. The store
owns its Tantivy index even with default CLI features disabled. `bench` enables
additional code-graph benchmark support. PDF extraction and semantic splitting are
optional ingest features. The declared `html`, `sheets`, `docx`, `watch` and
`pdf-minimal` flags remain deferred.

`scripts/ci/ci.sh` runs the feature matrix, tests, dependency gates, release build,
MCP smoke and size checks. It requires the documented platform tools; exit 3 means
verification was incomplete. `scripts/mcp/` and `scripts/tests/` contain Python checks.
See [scripts](scripts/README.md) for prerequisites and helper commands.

## Specifications and archives

Specifications live in a sibling `specs` checkout (`../specs/kaban/`), kept outside this
repository. Each stream folder (`00-project/`, `05-storage-search/`, ...) holds its spec, plan
and research; reviews, evidence and owner decisions sit in the stream's `archive/`. Start at
[the project index](../specs/kaban/00-project/README.md) and
[historical delivery protocol](../specs/kaban/00-project/archive/PROTOCOL.md).

Benchmark reports, schemas and shell/Python tooling are available in
[`specs/kaban/archive/benchmarks`](../specs/kaban/archive/benchmarks/README.md).
The external benchmark folders are excluded from this source tree. The Rust CLI
benchmark command and its required test fixtures remain available.
