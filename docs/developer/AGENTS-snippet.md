# The kaban instruction block for `AGENTS.md` / `CLAUDE.md`

kaban keeps the project's accepted decisions and conventions in two places an agent can read
without any tool: the committed digest `.kaban/adr/INDEX.md` (one `.kaban/<ontology>/INDEX.md`
per ontology with digest kinds; written by `kaban sync` and the `pre-commit` hook, core-spec
F9b, OWN-46) and a managed block inside `AGENTS.md` or `CLAUDE.md`
(written by `kaban export --write`, F9a). This file is the short instruction block that tells
the agent to use them. Copy it into your repository's `AGENTS.md` (or `CLAUDE.md`) once, by
hand, outside the managed block.

```
  session start                 before an edit                  the records themselves
  +--------------------+  =>   +-------------------------+  =>  +-------------------------------+
  | read               |       | call `why` for the path |      | .kaban/adr/decisions/<id>.md  |
  | .kaban/adr/INDEX.md|       | (MCP tool or kaban why) |      | .kaban/adr/conventions/<id>.md|
  +--------------------+       +-------------------------+      | .kaban/<ontology>/<dir>/<id>.md|
                                                                +-------------------------------+
```

## The block

```markdown
## Project memory (kaban)

- At session start, read `.kaban/adr/INDEX.md`: it lists the accepted Decisions and
  Conventions of this repository with their scope and rationale. Treat them as binding unless
  a newer accepted record supersedes them.
- Before editing a path, call the kaban `why` tool (or `kaban why --path <path>`) and follow
  the records that govern it. If a change contradicts a governing Decision, say so and propose
  a superseding Decision instead of silently diverging.
- Record new decisions with `remember` (kind `Decision`, with a `rationale`); a human accepts
  them (`kaban accept`). Proposed records are not binding.
- Do not edit `.kaban/<ontology>/**/*.md` or the text between `<!-- kaban:start -->` and
  `<!-- kaban:end -->` by hand: `kaban sync` and `kaban export --write` own those bytes.
```

## What touches these files

| File | Written by | Never by |
|---|---|---|
| `.kaban/<ontology>/INDEX.md`, `.kaban/<ontology>/<dir>/<id>.md` (shipped: `.kaban/adr/INDEX.md`, `.kaban/adr/decisions/<id>.md`) | `kaban sync` (and the `pre-commit` hook running it with `--stage`); the first engine `sync` moves a pre-engine `.kaban/<dir>/` tree once (`docs/developer/SYNC.md`) | the MCP server, the host hooks, `kaban export` |
| the managed block in `AGENTS.md` / `CLAUDE.md` | `kaban export --format agents-md --write AGENTS.md` (or `--format claude-md --write CLAUDE.md`), only between the markers; every byte outside is preserved | `kaban sync`, the hooks, the MCP server |
| the instruction block above | you, once, by hand | kaban |

The exported block carries one `generated by kaban export at <sha>` line and the same
instruction line as the first bullet above, so an agent that reads only `AGENTS.md` still
learns where the digest is. Re-running `kaban export --write` at the same commit is a no-op
(`unchanged`). `kaban sync` writes nothing outside `.kaban/`.

## Install checklist

1. Run `kaban serve` once through your MCP client (or `kaban doctor`) so the database exists.
2. `git config core.hooksPath hooks/git` (or copy `hooks/git/{pre-commit,post-commit}` into
   `.git/hooks/`), see `hooks/README.md`, "git hooks".
3. `kaban export --format agents-md --write AGENTS.md` for the managed block.
4. Paste the block above into `AGENTS.md` (outside the markers) and commit.
